# KEIHI — 領収証から、経費帳へ。

個人事業のための、小さなブラウザ経費帳。GitHub Pagesでそのまま配信する静的アプリです。サーバー処理・APIキー・有料OCRサービス・外部データベースは使いません。

## 使い方

1. 「設定・按分」で、仕事に使う割合と根拠を設定します。初期の家賃・通信費等の割合は未設定です。
2. 領収証を撮影するか、写真を選択します。写真は20枚まで順番に処理できます。
3. 必要に応じて回転・切り抜きを行い、「この写真を読み取る」を押します。
4. 蛍光色があればマークのある商品を選択します。なければ全商品を選択して開始します。家庭用品のチェックを外してください。
5. 商品直下の値引きと、会計全体のクーポンを確認します。値引き先は変更できます。
6. 日付・店名・科目・事業割合を確認し、紙の支払総額と照合して登録します。
7. 紙の領収証にも自動発行した整理番号を書き、月ごとにまとめて保管します。

手入力、登録後の編集・削除、検索、年・月・科目の絞り込み、月別・科目別集計、CSV出力、JSONのバックアップ・復元にも対応します。

## 計算方法

- 金額は円単位の整数。按分率は0～100%、小数点以下2桁までです。
- 商品値引きをその商品から控除します。
- 会計全体のクーポンは、家庭用の商品も含めた値引き後の商品金額に応じて配分します。端数は最大剰余法で配分し、値引き総額を維持します。
- 税抜きの場合は値引き後の金額に外税を加算し、税率別に実際の税額を入力できます。税込みの内税は重ねて加算しません。
- 選択した商品の税込金額に事業割合を掛けます。商品ごとに切り捨て・四捨五入・切り上げを選択できます。
- 家事按分の設定変更は過去の登録に反映しません。編集時も登録時の端数処理を保持します。
- 画像ハッシュ、または同じ日付・店名・支払総額で重複候補を表示します。
- レシート全体の明細合計と支払総額が不一致の場合、修正または理由の記録が必要です。小計を支払総額の代わりに自動採用しません。

ポイント利用は自動で値引き扱いにしません。複雑なセット割引、複数商品に限定したクーポンなどは、紙を見て対象と金額を調整してください。OCRや色検出は誤る場合があるため、必ず紙と照合して確定する設計です。

## データと画像

OCRは同梱のTesseract.js 7.0.0をWeb WorkerとWebAssemblyで動かします。蛍光マーカーは色と文字行の位置を照合します。画像はブラウザのメモリ内だけで処理し、サーバー・解析サービス・GitHubへ送信しません。登録または読み取り終了時にプレビューとワーカーを破棄します。

保存するのは日付・店名・商品名・科目・金額・割合・根拠・メモ・整理番号・画像のハッシュなどのテキストデータです。写真、サムネイル、画像のBase64、読取画像の自動ダウンロードは保存しません。OCRのIndexedDBキャッシュも無効です。通常のHTTPキャッシュにアプリやエンジンが残る場合はあります。

初期設定では明細のみlocalStorageへ保存します。「明細を端末に残す」をOFFにすると、明細は開いているタブ内だけで扱い、タブを閉じると消えます。バックアップ・CSVは利用者が押したときだけ出力します。端末変更やブラウザデータの削除前にバックアップしてください。

画像を保管するアプリではなく、紙の整理・読取・計算の補助です。電子帳簿保存法のスキャナ保存には対応していません。原本は利用者が保管します。所得税の経費集計用で、確定申告書や消費税申告書は作成しません。

家事按分の参照：国税庁「必要経費の知識」 https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2210.htm

## 開発・検証

ビルドと依存パッケージのインストールは不要です。Node.js 20以降で計算ロジックを検証できます。

```sh
npm test
npm run check
```

プレビューはこのフォルダをHTTP配信してください。画像読取・カメラ操作・ハッシュ計算のため、公開時はHTTPSを利用してください。GitHub PagesのHTTPSで動作します。

第三者のコード・日本語学習データは `vendor/` に同梱しています。詳細は [THIRD_PARTY.md](THIRD_PARTY.md) を参照してください。
